## Quality target
Move each interpretation meaningfully closer to the **experienced qualities** of its own source: authored movement, spatial continuity, material/light response, responsive feedback, scene/navigation transitions, scroll choreography and real manipulable elements where the source earns them. This is not a mandate for maximum animation, game controls, 3D everywhere or pixel copying. Editorial and lower-input concepts need equally deliberate execution without becoming games.

For every study:
1. Inspect its current DESIGN/SURFACE/PRODUCT and runtime plus accepted main/open-reading evidence. Read original BUILD_BRIEF, CONTENT_MOBILE_BRIEF and (for additions) EXPANSION_BRIEF for factual boundaries.
2. Revisit the exact `source_url` and, where present, `reference_url` in `preview/manifest.json`. Inspect actual rendered interaction sequences, not just one still. Preserve old archived recordings/research when live access fails; disclose observed versus proposed effects and source-device limitations. No invented live observations, certificate bypass or guessed credentials.
3. Write a short study-specific fidelity contract before editing: compelling source behaviors/qualities, current gap, focal interaction, continuity/feedback, mobile translation, renderer choice and performance budget. Retain proof of reference observations.
4. Implement meaningful reference-informed improvements. A generic particle overlay, card hover, global parallax or repeated fade-and-rise is not sufficient. Improve actual outcomes and continuity; do not add dead controls or promise that a production rebuild will supply the missing experience. Use the current renderer when it can support the intended interaction; a bounded renderer enhancement/conversion may be used if necessary while preserving the accepted scene identity and browsing topology. Document remaining material gaps candidly instead of renaming them as intentional style.
5. Keep the complete personal reading journey functional and world-native. No scenery-only polish that breaks About/Practice/Curiosity/contact/return. Preserve user-created/approved portraits and factual copy unless a narrowly necessary accessibility label changes.
6. Give phones an authored responsive interaction translation, not only smaller desktop or one static image while all interesting behavior disappears. Keyboard and touch must access core interactions; pointer reactions need non-pointer alternatives where they communicate meaningful state. Respect reduced motion with an intentional visible alternative. Pause/offscreen/hidden state must stop expensive loops; audio must be opt-in, never autoplay. Preserve useful no-JS and renderer-failure reading paths.
7. Verify actual code in a real Chromium browser: desktop, narrow/typical/wide portrait, landscape and tablet; overview and meaningful reading/contact states; real keyboard and trusted emulated touch; repeated/interrupted interactions; reduced motion and fallback; image/font loading, page errors and overflow. Record normal-motion evidence and measured render activity/performance, distinguishing software-rendered emulation from physical-device/GPU certification. Do not claim a normal-motion pass based only on reduced-motion screenshots.
8. Retain fresh state captures plus a short actual browser recording or chronological frames that demonstrate each focal interaction before/after/reversal. Screenshots alone cannot prove the requested experience. Record source/runtime hashes and executed test results. Run the detector once for this new pass, preserve raw output and label earlier detections historical.
9. Bound self-QA: one batched desktop/mobile/full-path inspection, one named repair/confirmation pass. Then deliver an honest handoff; independent parent review determines readiness, not a generic 'ship' assertion.
